# Skill: repo-and-path-topology
> **LOAD THIS FIRST, every session, before anything else.** Path confusion is the single most common silent-failure mode in Cue's history — it has produced at least two confirmed regressions (a session running Flutter edits against the wrong working directory, and a session editing a non-canonical CLAUDE.md). These failures are silent: no error, no warning, edits land in a plausible-looking wrong file. This skill is the guard against that.
## When to use
At the start of EVERY session, and any time you are about to edit a file, commit, push, or run a build. If you are unsure which repo or which file you are in, you are in the dangerous state this skill exists to prevent.
## The two repos
Cue lives across **two separate git repositories** with **two separate deploy pipelines.** They do not share git history. A change to one does not deploy the other.
| Repo | Local path | Remote | Contains | Deploys to |
|---|---|---|---|---|
| **Flutter web app** | `C:\projects\cue` | `cheGv/cue-flutter` | `lib/`, all Dart, screens, theme tokens, cuttlefish widget, Cue Study UI, Goal Authoring UI | Netlify / GitHub Pages on commit to `main` |
| **Proxy** (Node/Render) | `C:\dev\cue\proxy` | `cheGv/cue-ai-proxy` | `server.js`, `routes/generateGoals.js`, the system prompts for Cue Study / Brief / Generate Plan | Render on commit to that repo's `main` |
## The canonical CLAUDE.md — and the decoy
**The ONLY governance CLAUDE.md for the Flutter app is `C:\projects\cue\CLAUDE.md`.** Every session that edits Flutter governance edits THIS file.
> **⚠️ THE DECOY ⚠️** There is also a file at `C:\Users\guruv\OneDrive\Desktop\Cue\CLAUDE.md`. It is a short NORTH STAR brief, separate from the canonical project document. **DO NOT EDIT THIS FILE.** Do not assume it contains current architecture. If a session finds itself editing this file, it is in the WRONG LOCATION — restore it from git or from Guru, then redirect edits to `C:\projects\cue\CLAUDE.md`. This decoy has already caused one confirmed regression.
The proxy repo has its own governance (`C:\dev\cue\proxy\CLAUDE.md` + `.claude/skills/`), separate from the Flutter app's.
## Path rules
- Any session touching **Flutter code** (anything in `lib/`, any `.dart`, any theme token, any screen) runs from `C:\projects\cue`.
- Any session touching **proxy code** (`server.js`, system prompts, `routes/`, Node-side anything) runs from `C:\dev\cue\proxy`.
- Any session **editing Flutter governance** edits `C:\projects\cue\CLAUDE.md` and only that file.
- Any session **editing proxy governance** edits `C:\dev\cue\proxy\CLAUDE.md` and only that file.
## The first commands of every session
```
# Confirm working directory
pwd                          # (PowerShell: Get-Location)
# Confirm which CLAUDE.md is reachable
Get-ChildItem CLAUDE.md      # (or: ls CLAUDE.md)
# Confirm which repo you're in
git remote -v                # cue-flutter? or cue-ai-proxy?
```
**Mismatches between expected and actual path are the most common silent failure mode in Cue.** Run these three checks before trusting that you're in the right place. The ten seconds they take has a two-regression track record of being worth it.
## Shared skills live in the Flutter repo; the proxy points at them
The shared-core skills (`north-star`, `product-law`, `clinical-invariants`, `language-discipline`) are physically canonical in `C:\projects\cue\.claude\skills\_shared\`. The proxy repo does NOT duplicate them (duplication causes drift). Instead, the proxy's governance points to them. When working in the proxy on anything that touches clinical voice or product law, read the shared skills from the Flutter repo path — they govern proxy prompts as much as Flutter code.
## How to recover from path confusion
If a session has already edited the wrong file:
1. Restore it — `git checkout -- <file>` if tracked, or restore from Guru's original.
2. Redo the intended edits at the correct path.
3. Document the recovery so the next session understands what happened.
Do NOT panic and do NOT attempt a history rewrite to "clean up" — restore the file, redo correctly, move on.
## Anti-rationalizations
| Excuse | Counter |
|---|---|
| "I'm obviously in the right repo, skip the pwd check." | The two confirmed regressions both felt obvious. Run the three checks anyway. |
| "This CLAUDE.md looks right, I'll edit it." | The decoy looks plausible too. Confirm it's `C:\projects\cue\CLAUDE.md`, not the OneDrive Desktop path. |
| "I'll push the proxy change from the Flutter working tree." | Different remote, different pipeline. Push proxy from `C:\dev\cue\proxy` only. |
| "I'll copy the shared skills into the proxy so they're handy." | That's the drift trap. Point at them; don't duplicate. |
## Evidence of compliance
- Session opened with `pwd` + `Get-ChildItem CLAUDE.md` + `git remote -v` confirmed.
- Any CLAUDE.md edit confirmed to be the canonical path, not the decoy.
- Any push confirmed to be from the correct repo's working tree.
